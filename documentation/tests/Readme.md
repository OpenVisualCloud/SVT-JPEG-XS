# Testing

Steps to execute different levels of tests:

## Sample files

Set of sample files should be downloaded to server.
Set environment variable INPUT_FILES_PATH to point there.

The scripts expect this layout under INPUT_FILES_PATH:

| Directory | Used by |
| -- | -- |
| `test_bitsreams/` | Decoder conformance tests (input `.jxs` streams) |
| `reference_decode/` | Decoder conformance tests (expected decoded `.yuv`) |
| `bitstream_multi_frames/` | Decoder multi frames tests |
| `bitstream_invalid/` | Decoder multi frames tests (invalid streams) |
| `encoder_tests/` | Encoder tests, performance tests, and sources for streams generated by the decoder tests |

## Common test script options

DecoderConformanceTest.sh, DecoderMultiFramesTest.sh, EncoderTest.sh and the FFmpeg/GStreamer test scripts take
`<samples> <binary>` as the first two arguments, followed by optional arguments (see `tests/scripts/CommonLib.sh`):

- `valgrind`: run every test under valgrind
- `range:X`: run only test with id X
- `range:X-Y`: run only tests with id X <= id < Y
- `fast`: run reduced number of tests, for example only AVX2 (DecoderConformanceTest.sh, DecoderMultiFramesTest.sh and
  EncoderTest.sh only)
- `dec`: encoder tests also decode the produced streams to verify them, and leave the results in the temp directory
- `tmp:<dir>`: use `<dir>` as temp directory (default `tmp`)
- `num`: only count the tests, nothing is executed
- `help`: print help and exit

If environment variable SANITIZER_ASM is set, DecoderConformanceTest.sh, DecoderMultiFramesTest.sh and EncoderTest.sh
replace every `--asm` option passed to the encoder/decoder apps with its value (or append `--asm $SANITIZER_ASM`), so all
tests run on a single ISA path. It is used by `sanitize.sh`.

## Build

```bash
cd Build/linux
./build.sh test
cd ../..
```

## Execute sequential tests

### Decoder Conformance Test

```bash
cd tests/scripts
./DecoderConformanceTest.sh $INPUT_FILES_PATH ../../Bin/Release/SvtJpegxsDecApp
cd ../..
```

### Decoder Multi Frames Test

```bash
cd tests/scripts
./DecoderMultiFramesTest.sh $INPUT_FILES_PATH ../../Bin/Release/SvtJpegxsDecApp
cd ../..
```

### Encoder Test

```bash
cd tests/scripts
./EncoderTest.sh $INPUT_FILES_PATH ../../Bin/Release/SvtJpegxsDecApp
cd ../..
```

### Unit Test

```bash
Bin/Release/SvtJpegxsUnitTests
```

## Execute parallel tests

### Run all tests parallel

This command runs parallelly the files:

- DecoderConformanceTest.sh
- DecoderMultiFramesTest.sh
- EncoderTest.sh

```bash
cd tests/scripts
./ParallelAllTests.sh $(nproc) $INPUT_FILES_PATH ../../Bin/Release/SvtJpegxsDecApp
cd ../..
```

### Unit Test parallel

```bash
tests/scripts/parrallelUT.sh Bin/Release/SvtJpegxsUnitTests $(nproc)
```

Run the unit tests under valgrind (fails on any memcheck error) by passing `valgrind` as third argument:

```bash
tests/scripts/parrallelUT.sh Bin/Release/SvtJpegxsUnitTests $(nproc) valgrind
```

Debug unit tests are built with `./build.sh debug test` (or `./build.sh --all test` for both Debug and Release) and run
from `Bin/Debug/SvtJpegxsUnitTests`.

### Unit Test on Windows

```bat
cd Build\windows
build.bat 2022 release test
```

Then from a bash shell (for example Git Bash), run the tests from the binary directory:

```bash
cp tests/scripts/parrallelUT.sh Bin/Release/
cd Bin/Release
./parrallelUT.sh ./SvtJpegxsUnitTests.exe $(nproc)
```

## FFmpeg plugin tests

Build FFmpeg with the SVT-JPEG-XS plugin from the repository root, for example
`.github/scripts/build_ffmpeg_plugin.sh 9.0 y` (FFmpeg is installed to `install-dir/`).
Scripts: FFmpegDecoderConformanceTest.sh, FFmpegDecoderMultiFramesTest.sh, FFmpegEncoderTest.sh. Each takes the ffmpeg
binary in place of SvtJpegxsDecApp. Run all of them in parallel:

```bash
cd tests/scripts
export LD_LIBRARY_PATH=../../install-dir/lib
./ParallelAllFFmpegTests.sh $(nproc) $INPUT_FILES_PATH ../../install-dir/bin/ffmpeg dec
cd ../..
```

`dec` is optional, it enables decode verification in FFmpegEncoderTest.sh. When the ffmpeg build has no `jpegxs_pipe`
demuxer, FFmpegDecoderMultiFramesTest.sh and the decode verification are skipped.

## GStreamer plugin tests

Build SVT-JPEG-XS and a minimal GStreamer with the svtjpegxs plugin from the repository root with
`.github/scripts/build_gstreamer_plugin.sh`. It writes `gst-plugin-env.sh`, which must be sourced before running the tests.
Scripts: GstreamerDecoderConformanceTest.sh, GstreamerDecoderMultiFramesTest.sh, GstreamerEncodeTest.sh. Each takes
INPUT_FILES_PATH only (`gst-launch-1.0` is taken from PATH). Run all of them in parallel:

```bash
source gst-plugin-env.sh
cd tests/scripts
./ParallelAllGstreamerTests.sh $(nproc) $INPUT_FILES_PATH
cd ../..
```

## Performance tests

- `PerformanceTestSampleApp.sh [samples] [avx512|avx2|sse|c]`: measures `Bin/Release/SvtJpegxsEncApp` and
  `Bin/Release/SvtJpegxsDecApp`. The default asm level is `avx512`, the only level checked against baselines; other levels
  are reported only.
- `PerformanceTestFfmpegPlugin.sh [samples]`: measures `ffmpeg` found on PATH.
- `PerformanceTestGstreamer.sh [samples]`: measures `gst-launch-1.0` with the svtjpegxs plugin (source `gst-plugin-env.sh`
  first).

The samples directory defaults to `Conformance-tests` in the repository root. The scripts require:

- passwordless `sudo` to create a tmpfs ramdisk under `/mnt` and to set the CPU frequency governor (see
  [self-hosted-runner-setup.md](../ci-cd/self-hosted-runner-setup.md#privileges))
- `numactl`; `perf_numa.sh` selects the NUMA node and CPUs the measured process is pinned to, and `perf_governor.sh` sets
  the `performance` governor for the duration of the run and restores it afterwards

Results are appended to `svt_app_results.csv`, `ffmpeg_results.csv` or `gstreamer_results.csv` in `tests/scripts`.

```bash
cd tests/scripts
export LD_LIBRARY_PATH=../../Bin/Release
./PerformanceTestSampleApp.sh $INPUT_FILES_PATH
cd ../..
```

## OOMify test

`OomifyTest.sh <bin_dir> <oomify_dir>` injects a `malloc()` failure at every allocation point in SvtJpegxsEncApp and
SvtJpegxsDecApp found in `<bin_dir>` and checks that each failure exits cleanly. `<oomify_dir>` must contain `oomify` and
`liboomify.so` built from <https://github.com/tavianator/oomify>, and libSvtJpegxs must be reachable through
LD_LIBRARY_PATH.

```bash
export LD_LIBRARY_PATH=$PWD/install-dir/lib
tests/scripts/OomifyTest.sh $PWD/install-dir/bin <oomify_dir>
```

## Sanitizer tests

`tests/scripts/sanitize.sh <address|thread|undefined|integer|memory> [--samples DIR] [--no-build]` builds with the
sanitizer (clang), runs the conformance test scripts sequentially and prints a findings report generated by
`tests/scripts/sanitizer_summary.sh`. See [run-jpegxs-tests SKILL.md](../../.github/skills/run-jpegxs-tests/SKILL.md) for
details.
